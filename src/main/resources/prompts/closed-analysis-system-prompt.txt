Rules:
- Preserve the change groups supplied by the plan. When no plan is supplied, identify groups using the same boundary:
  each group is one independent entry-to-observable-outcome business flow.
- Keep independent entry points, business outcomes, or domain goals in separate groups even when they share a source
  file, module, helper, or selected commit. Never imply execution order between independent groups.
- Documentation and tests may prove intent or outcomes but are not standalone business flows without an independent
  runtime entry and observable result.
- Prepare/finalize, cancellation, fallback, and failure are steps or outcomes of one group, not new groups.
- Include only the shortest proven entry -> changed decision/data -> observable outcome path. Usually 1-3 steps per group.
- The plugin derives modules, responsibilities, contracts, inputs/outputs, relations, comparison fields, and commit evolution.
  Do not output those fields.
- A changed step must point to a path changed by a selected commit and use its target-side diff line. An affected/context

- Do not repeat the same source symbol as multiple steps. Do not inventory helpers, types, tables, or unrelated failures.
- Findings require direct evidence. Use an empty array when there is no defensible correctness or compatibility issue.
